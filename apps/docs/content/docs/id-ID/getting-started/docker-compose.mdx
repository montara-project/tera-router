title: Docker Compose
description: Deploy API server dan dashboard Tera Router sebagai satu container dengan Docker Compose.
---

Image release di `ghcr.io/montara-project/tera-router` menggabungkan API server dan dashboard yang
sudah di-build dalam satu container — server menyajikan dashboard di port yang sama, jadi UI dan
gateway berbagi satu origin. Database SQLite disimpan di named volume dan tetap utuh saat image
di-upgrade.

## Prasyarat

- Docker dengan plugin Compose.
- Mesin yang bisa diakses dari browser (langsung atau di belakang reverse proxy).

## 1. Ambil file compose

Repo menyertakan `deploy/docker-compose.yaml` siap pakai: satu service `app` — API server yang
menyajikan dashboard hasil build di port yang sama — plus sidecar Headroom opsional di balik
profile. Setiap flag server jatuh ke environment variable-nya, jadi file ini tidak butuh daftar
`command:`; blok `environment:` di bawah adalah seluruh konfigurasi.

```yaml
services:
  app:
    image: ghcr.io/montara-project/tera-router:v1.23.0
    restart: unless-stopped
    # APP_PORT adalah port host; container selalu listen di 8080.
    ports:
      - '${APP_PORT:-8080}:8080'
    environment:
      ENV: ${APP_ENV:-production}
      MACHINE_ID: ${APP_MACHINE_ID:?APP_MACHINE_ID is required}
      APP_SECRET: ${APP_SECRET:?APP_SECRET is required}
      DEBUG: ${APP_DEBUG:-false}
      ADMIN_EMAIL: ${APP_ADMIN_EMAIL:-admin@tera.local}
      ADMIN_PASSWORD: ${APP_ADMIN_PASSWORD:?APP_ADMIN_PASSWORD is required}
      APP_NAME: ${APP_NAME:-tera-router-server}
      CORS_ALLOWED_ORIGINS: ${APP_CORS_ALLOWED_ORIGINS:-*}
      RATE_LIMIT_EXEMPT_IPS: ${RATE_LIMIT_EXEMPT_IPS:-}
      TRUSTED_PROXIES: ${TRUSTED_PROXIES:-}
      # Diinject ke web UI yang diserve saat runtime; isi hanya bila API
      # berada di origin lain dari dashboard.
      API_URL: ${API_URL:-}
      DATABASE_PATH: /app/data/terarouter.db
      MIGRATE_ON_BOOT: 'true'
      SEED_ON_BOOT: ${SEED_ON_BOOT:-true}
      SENTRY_DSN: ${SENTRY_DSN:-}
      # SSO dashboard lewat provider OIDC apa pun (Pocket ID, Keycloak, …).
      OIDC_ISSUER: ${OIDC_ISSUER:-}
      OIDC_CLIENT_ID: ${OIDC_CLIENT_ID:-}
      OIDC_CLIENT_SECRET: ${OIDC_CLIENT_SECRET:-}
      OIDC_PROVIDER_NAME: ${OIDC_PROVIDER_NAME:-}
      OIDC_REDIRECT_URL: ${OIDC_REDIRECT_URL:-}
      HEADROOM_URL: ${HEADROOM_URL:-http://headroom:8787}
      HEADROOM_PROXY_TOKEN: ${HEADROOM_PROXY_TOKEN:-}
    healthcheck:
      test: ['CMD', 'wget', '-qO-', 'http://127.0.0.1:8080/health', '||', 'exit', '1']
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 10s
    volumes:
      - tera-data:/app/data
    depends_on:
      headroom:
        condition: service_started
        required: false

  # Aktifkan dengan `docker compose --profile headroom up` dan
  # HEADROOM_PROXY_TOKEN yang sama di kedua service.
  headroom:
    image: ghcr.io/headroomlabs-ai/headroom:${HEADROOM_VERSION:-0.41.0}
    profiles: [headroom]
    restart: unless-stopped
    environment:
      HEADROOM_HOST: '0.0.0.0'
      HEADROOM_PORT: '8787'
      HEADROOM_COMPRESS_ALLOW_REMOTE: '1'
      HEADROOM_PROXY_TOKEN: ${HEADROOM_PROXY_TOKEN:-}
      HEADROOM_DISABLE_KOMPRESS: ${HEADROOM_DISABLE_KOMPRESS:-1}
      HEADROOM_DISABLE_KOMPRESS_FALLBACK: ${HEADROOM_DISABLE_KOMPRESS_FALLBACK:-1}

volumes:
  tera-data:
```

Dua cara menjalankannya:

- **Dari checkout repo** — `docker compose -f deploy/docker-compose.yaml up -d` mem-build image dari
  `deploy/Dockerfile` lalu menjalankan stack.
- **Standalone** — salin filenya, hapus blok `build:`, dan arahkan `image:` ke tag release, mis.
  `ghcr.io/montara-project/tera-router:v1.22.0`.

<Callout type="warn" title="Konfigurasi env-only butuh image terbaru">
  Membaca konfigurasi dari environment saja baru tersedia di release setelah `v1.22.0`. Untuk pin
  `v1.22.0` hari ini, pertahankan blok `environment:` yang sama tapi tambahkan `command:` yang
  meneruskan nilainya sebagai flag (`--machine-id`, `--app-secret`, …) — nama flag-nya sama dengan
  env versi kebab-case.
</Callout>

## 2. Buat `.env`

Letakkan di samping file compose (`deploy/.env` bila dijalankan dari repo) lalu isi nilainya:

```bash
# Wajib — Compose menolak interpolasi tanpa ini
APP_MACHINE_ID=1
APP_SECRET=generate_from_openssl_rand_base64_48
APP_ADMIN_PASSWORD=your_password

# Akun admin yang diseed
APP_ADMIN_EMAIL=your@email.com

# App
APP_ENV=production
APP_DEBUG=false
APP_PORT=8080
APP_NAME=tera-router-server
APP_CORS_ALLOWED_ORIGINS=*

# IP klien yang bebas dari rate limit dashboard (dipisah koma)
RATE_LIMIT_EXEMPT_IPS=
# Proxy yang dipercaya menyuplai X-Forwarded-For (IP/CIDR dipisah koma)
TRUSTED_PROXIES=

# Isi hanya bila API berada di origin lain dari dashboard
API_URL=

# Seed data awal saat boot (role, admin, plan Default)
SEED_ON_BOOT=true
SENTRY_DSN=

# SSO dashboard lewat provider OIDC (Pocket ID, Keycloak, …); tombol login
# muncul hanya bila issuer + client id + secret semuanya terisi
OIDC_ISSUER=
OIDC_CLIENT_ID=
OIDC_CLIENT_SECRET=
OIDC_PROVIDER_NAME=Pocket ID
OIDC_REDIRECT_URL=

# Sidecar Headroom (--profile headroom)
HEADROOM_PROXY_TOKEN=
HEADROOM_VERSION=0.41.0
```

<Callout type="error" title="APP_SECRET adalah kunci utama">
  `APP_SECRET` menandatangani token sesi dan menurunkan kunci yang mengenkripsi kredensial provider
  yang tersimpan. Compose menolak jalan tanpa itu. Pakai minimal 32 karakter acak (`openssl rand
  -base64 48`); server memberi peringatan saat boot kalau lebih pendek. Menggantinya belakangan
  membuat semua kredensial yang tersimpan tidak bisa dibaca — set sekali dan simpan baik-baik.
</Callout>

## 3. Jalankan stack

```bash
docker compose -f deploy/docker-compose.yaml up -d
docker compose -f deploy/docker-compose.yaml logs -f app
```

Saat boot, container akan:

1. Menjalankan migrasi SQLite yang belum diterapkan (`MIGRATE_ON_BOOT`).
2. Menyeed data awal (`SEED_ON_BOOT`) — role, user admin dari `ADMIN_EMAIL`/`ADMIN_PASSWORD`, dan
   plan _Default_.
3. Membuka gateway (`/v1/*`), dashboard API, dan UI dashboard di port yang sama (`APP_PORT`,
   default `8080`).

Compose melaporkan `healthy` setelah healthcheck bawaan lulus
(`wget http://127.0.0.1:8080/health` dari dalam container). Lalu buka `https://yourdomain.com`
(atau `http://<host>:8080` langsung) dan masuk dengan akun admin yang diseed.

## Catatan produksi

- **Trusted proxies** — `TRUSTED_PROXIES` harus cocok dengan subnet tempat reverse
  proxy atau load balancer kamu benar-benar berada, supaya server membaca IP klien asli untuk rate
  limiting dan log. Sesuaikan nilainya sebelum deploy. Di belakang Cloudflare dan Traefik, lihat
  [di bawah](#di-belakang-cloudflare-dan-traefik-dokploy).
- **Blokir IP** — **Settings → Security → Blocked IPs** menolak alamat atau rentang CIDR dengan 403,
  dan alamat yang gagal login 10 kali dalam 15 menit diblokir selama 15 menit. Keduanya memakai IP
  klien, jadi atur trusted proxies dulu: kalau tidak, semua pengunjung terlihat memakai alamat proxy
  dan login gagal dari satu penyerang akan memblokir semua orang.
- **Pengecualian rate limit** — `RATE_LIMIT_EXEMPT_IPS` menerima daftar IP terpisah koma yang
  melewati rate limit dashboard (mis. host monitoring internal).
- **Token saving (opsional)** — `deploy/docker-compose.yaml` di repo menyertakan sidecar Headroom
  di balik profile `headroom`: `docker compose --profile headroom up -d` dengan
  `HEADROOM_PROXY_TOKEN` yang sama di kedua service (`openssl rand -hex 32`). Server menjangkaunya
  lewat `HEADROOM_URL` (`http://headroom:8787`); nyalakan di **Settings → Token Saving**.
- **Persistensi** — semua yang stateful adalah file SQLite di `/app/data/terarouter.db` pada volume
  `tera-data`. Masukkan ke rutinitas backup kamu.
- **Upgrade** — naikkan tag image, lalu `docker compose up -d`. Migrasi yang belum diterapkan
  berjalan saat boot selama `MIGRATE_ON_BOOT=true`; mem-pin tag menjaga bundle dashboard dan binary
  server tetap sinkron.

## Di belakang Cloudflare dan Traefik (Dokploy)

Saat request melewati klien → Cloudflare → Traefik → container, ada dua hop di depan server.
Traefik membuang `X-Forwarded-For` yang datang dari alamat yang tidak ia percaya dan menggantinya
dengan IP edge Cloudflare, sehingga semua pengunjung terlihat sebagai Cloudflare. Percayai kedua hop:

1. **Traefik memercayai Cloudflare.** Di konfigurasi Traefik Dokploy (biasanya
   `/etc/dokploy/traefik/traefik.yml`), tambahkan rentang IP Cloudflare ke kedua entrypoint, lalu
   restart Traefik. Cocokkan daftarnya dengan [cloudflare.com/ips](https://www.cloudflare.com/ips/)
   karena bisa berubah.

   ```yaml title="traefik.yml"
   entryPoints:
     web:
       address: ':80'
       forwardedHeaders:
         trustedIPs: &cloudflare
           - 173.245.48.0/20
           - 103.21.244.0/22
           - 103.22.200.0/22
           - 103.31.4.0/22
           - 141.101.64.0/18
           - 108.162.192.0/18
           - 190.93.240.0/20
           - 188.114.96.0/20
           - 197.234.240.0/22
           - 198.41.128.0/17
           - 162.158.0.0/15
           - 104.16.0.0/13
           - 104.24.0.0/14
           - 172.64.0.0/13
           - 131.0.72.0/22
           - 2400:cb00::/32
           - 2606:4700::/32
           - 2803:f800::/32
           - 2405:b500::/32
           - 2405:8100::/32
           - 2a06:98c0::/29
           - 2c0f:f248::/32
     websecure:
       address: ':443'
       forwardedHeaders:
         trustedIPs: *cloudflare
   ```

   Yang baru hanya blok `forwardedHeaders`: gabungkan ke entrypoint Dokploy yang sudah ada dan
   biarkan bagian lain (providers, TLS, `certificatesResolvers`) apa adanya. Traefik sekarang
   meneruskan `X-Forwarded-For: <klien>, <edge-cloudflare>`.

2. **tera-router memercayai Traefik dan Cloudflare.** Isi `TRUSTED_PROXIES` dengan subnet network
   Docker tempat Traefik berjalan ditambah rentang Cloudflare yang sama, dipisah koma:

   ```bash
   docker network inspect dokploy-network --format '{{(index .IPAM.Config 0).Subnet}}'
   ```

   ```bash title=".env"
   TRUSTED_PROXIES=10.0.1.0/24,173.245.48.0/20,103.21.244.0/22,...,2c0f:f248::/32
   ```

   Tanpa subnet Traefik, header diabaikan (peer langsungnya adalah Traefik). Tanpa rentang
   Cloudflare, server berhenti di IP edge dan melaporkannya sebagai klien.

Server membaca `X-Forwarded-For` dari kanan ke kiri dan mengambil alamat pertama yang bukan trusted
proxy, jadi isian palsu dari klien di sebelah kiri dilewati. Request yang melewati Cloudflare dan
langsung mengenai origin datang dari alamat yang tidak dipercaya: Traefik membuang header
forwarded-nya dan server melihat IP asli pemanggil. Jangan beralih ke `CF-Connecting-IP`: Traefik
meneruskannya apa adanya, sehingga siapa pun yang mengakses origin langsung bisa memalsukannya.
Opsional, batasi port 80/443 di firewall hanya untuk rentang Cloudflare agar origin tidak bisa
diakses tanpa lewat Cloudflare.

Untuk memastikan, coba login gagal dari jaringan lain (mis. HP dengan data seluler) lalu cek
**Settings → Security**: alamat yang tercatat harus IP HP, bukan IP Cloudflare atau `10.x`.
